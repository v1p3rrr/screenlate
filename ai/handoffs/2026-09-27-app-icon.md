## What was done and decided

The owner chose, in steps: six concepts → four developed (bubble and card, aimed word, card over the screen, lifted
word) → variants in several palettes → variants in the overlay's own colors and style → the final one, X2:

- A word lifted out of a line of text: grey rows (`#2E2848` at 32%, the owner asked for more contrast than 20%), the
  word's former place highlighted in `#7C5CFF` at 30%, the bubble's aim dot on that place with a white outline, the
  word itself solid `#7C5CFF` above the rows. White background `#F8F6FD` (the owner accepted that the icon's edge
  disappears on white wallpapers). No letters of any language.
- Debug build ("Screenlate Dev"): the same icon with a dark badge and an amber bug at the lower right, about a third of
  the icon wide (the owner asked for a badge large enough to notice).
- Themed icon (Android 13+): monochrome layer with translucency kept; the aim dot's outline and the bug are gaps.
- Quick Settings tile and import notification: the icon's silhouette at 24 dp instead of the ring and the book.
- README: the icon without a wordmark.

- CI run by hand on the branch passed (build, unit tests, lint without errors, page tests):
  https://github.com/v1p3rrr/screenlate/actions/runs/36332781284, debug APK in the artifact `screenlate-debug-32f3657`.

## Check locally

1. Build and tests: `./gradlew assembleDebug testDebugUnitTest lintDebug`. Lint must not report new issues for the
   icon files (e.g. `VectorPath`, `MonochromeLauncherIcon`, `IconLauncherShape`).
2. Optional: regenerate and check the icon (`pip install fonttools skia-pathops`, Playwright for Node):
   `python3 scripts/icon/icon.py && node scripts/icon/check.mjs`; `git status` must stay clean.
3. Emulator: `scripts/debug-device.sh install` (debug build). For release next to it:
   `./gradlew assembleRelease -Pscreenlate.debugSignedRelease` and
   `adb install -r app/build/outputs/apk/release/app-release.apk`.
   - Launcher icon on the home screen and in the app drawer (Pixel launcher): readable, nothing clipped; try other icon
     shapes if the launcher offers them.
   - Themed icon (Android 13+): Wallpaper & style → Themed icons on; the silhouette with lighter rows, the aim dot's
     gap visible, the debug badge recognizable.
   - Splash screen (Android 12+, cold start: `adb shell am force-stop com.vpr.screenlate.debug`, then open the app):
     the icon is shown in a circle on the window background; check it is not clipped and does not look broken.
   - App info (Settings → Apps → Screenlate) and recent apps.
   - Quick Settings tile: add "Screenlate" to the shade, check the icon when on and off.
   - Import notification: start a dictionary import (a catalog download or a file); check the icon in the status bar
     and in the notification.
   - Debug and release side by side: the badge tells them apart at a glance.
4. The owner's phone (Honor, MagicOS 9): the same list, plus MagicOS icon shapes and themes if available (MagicOS
   may draw adaptive icons with its own mask, or put them on a plate).

Take screenshots of each point (`scripts/debug-device.sh shot <file>`).

## If something is wrong

- Technical problems (the build, lint, a missing or clipped layer, a wrong resource): fix them on the branch. Change
  the design in `scripts/icon/icon.py`, regenerate, run `check.mjs`, never edit the generated XML by hand.
- Design problems (looks wrong on a launcher, unreadable somewhere, the splash screen looks off): do not redesign on
  your own. Send the owner the screenshots, say what is wrong, and propose options.

## When everything is fine

Merge `claude/elegant-allen-xmu3fx` into main (the collection import too, if it is not merged yet: check it per its
handoff first), push, and update `ai/status.md` (remove the "Verify branch…" items from Next) and the "Checked only on
a device" section of `ai/notes/app-icon.md` with what was seen on the emulator and the phone.
