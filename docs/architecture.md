# Architecture

## Modules

```
app ──────────────┬──> overlay ──┬──> core:ocr ──> core:common
                  │              ├──> core:anki ─> core:common
                  │              ├──> core:translate ──> core:common
                  │              └──> dictionary:api ──> core:common
                  ├──> dictionary:engine-hoshidicts ──> dictionary:api
                  └──> dictionary:render-yomitan (assets only)
```

| Module | Contents |
|---|---|
| `app` | Application (Hilt, WorkManager factory), Compose screens: home with setup warnings, search, one Settings screen leading to bubble, lookup, dictionaries, Anki and audio, popup, translation (`translate/`), appearance (theme, e-ink mode, language, popup font and CSS), Yomitan import, backup and restore (`backup/`), background work and About; OCR test. The dialog about what the accessibility service reads and sends comes before its settings open until the user agrees (`home/AccessibilityDisclosure`). `ProcessTextActivity` for the text selection menu. |
| `overlay` | Accessibility service, bubble state machine (`OverlayController`), window screenshots, app text from the accessibility tree, the lookup page (`web/LookupPage`, `assets/popup/`), popup placement, crop editor, Anki buttons (`anki/PopupNotes`), page fonts and custom CSS (`fonts/`), Quick Settings tile (holding it opens the app through `BubbleTileSettingsActivity`), the optional keep-alive foreground service (`BubbleKeepAliveService`), the service's running state for the start screen (`OverlayServiceStatus`). |
| `core:common` | `Language` and `LanguageSupport` (everything language-specific: lookup start, spelling variants, romaji, sentence rules, fonts, audio defaults), `MappedText`, geometry, app settings, shared OkHttp client, local network address checks, log redaction. |
| `core:ocr` | `OcrEngine` with a cloud engine (hand-written protobuf) and the device (`DeviceOcr`: ML Kit, or an engine with downloaded models from `OcrModelStore`), `CompositeOcr` (draft, then final), `TextLayout` for hit testing. |
| `core:anki` | AnkiDroid API wrapper behind `AnkiBackend`, note settings, field templates, sentence extraction, setup status, audio sources and playback. |
| `core:translate` | `SentenceTranslator` over the Bing, Google and Edge translators (`Translator`), the language table (generated by `scripts/translation/languages.py`), translation settings. |
| `dictionary:api` | `DictionaryEngine` interface and lookup models, registry (Room), import queue (WorkManager), bundled dictionaries, download catalog, update check, `YomitanSorter`, Yomitan collection export converter. |
| `dictionary:engine-hoshidicts` | `DictionaryEngine` on top of hoshidicts (C++, JNI). GPL-3.0. |
| `dictionary:render-yomitan` | JavaScript and CSS that render Yomitan structured content, images, furigana and pitch accent. GPL-3.0. |

The two GPL modules implement interfaces or asset contracts defined elsewhere, so they can be replaced without touching the rest.

## From the bubble to a dictionary entry

1. **Scan.** Pulling the bubble out of the dock (or tapping it) takes a screenshot of the app window under the overlays (`takeScreenshotOfWindow`, API 34+; older versions capture the display with the overlays hidden for a frame), so the popup is never recognized and the text under it is. With "Read app text", `AccessibilityText` reads the application windows' accessibility tree while the screen is captured, and OCR runs as well. Neither waits for the other: whichever is ready is shown, and app text takes precedence where both have text, with OCR adding only the lines app text lacks. "App text only" skips the screenshot and OCR (the screenshot is taken later only when a note asks for a picture). Nodes whose character boxes cannot be trusted are left to OCR: the same box for every character (a WebView reporting the node's bounds) and text fields whose first box sits at the field's corner (Compose fields, whose boxes include the padding).
2. **OCR.** `CompositeOcr` runs ML Kit on the device and the cloud engine in parallel. ML Kit first reads a band of the screen around the aim (`FocusBand`, again when the aim has moved out of it), then the whole screen; each result is shown as a draft until the cloud result replaces it. ML Kit's time grows with the amount of text, so the band is ready several times sooner than the whole screen. The model is loaded when the bubble starts. The cloud engine gets a JPEG of at most 1500 px; its coordinates are normalized to the image and mapped back to the screen. `OcrOptions` can limit a scan to one engine or defer ML Kit's whole-screen pass until the cloud engine is 3 s late or fails (`deferWholeImage`). ML Kit's symbol boxes sometimes lag behind the glyphs by up to half a character; `SymbolLag` moves the inner boundaries of such words onto the gaps between glyphs when the pixels clearly show them.
3. **Hit test.** `TextLayout` splits every recognized word into characters (per-character boxes when the engine has them, otherwise even splits along the reading direction) and finds the character under the aim point. The text from that character to the end of its paragraph, up to the scan length (16 characters by default), is the lookup text; in a language written with spaces it starts at the beginning of the word under the aim. Words, and the lines of a paragraph, are joined by each word's separator (none in Japanese), so a phrase broken across lines is still found. `ReadingOrder` puts paragraphs into reading order first: vertical columns right to left, and a column that runs to the bottom of its text joined with the column that goes on from it, so a word broken at a line or column end is read as a whole.
4. **Lookup.** `DictionaryLookup` loads the enabled dictionaries into the engine on first use. hoshidicts deinflects every prefix of the lookup text, groups results by expression and reading, and sorts them; `YomitanSorter` applies Yomitan's full order including dictionary priority. The language's spelling variants (`LanguageSupport.spellingVariants`) and, when enabled, romaji converted to kana are looked up as well; `MappedText` maps their matched lengths back to the screen text. Other languages go through Yomitan's own language code: a bundle per language (`assets/yomitan-language`, built by `scripts/yomitan-language`) runs in QuickJS inside the engine library and turns the text into candidates with the language's text processors (such as decapitalizing) and deinflection rules, and hoshidicts answers exact queries for them. Form-of entries (a form pointing to its lemma, which Wiktionary dictionaries hold by the million) are split out of an archive at import into a compact table next to the dictionary, memory-mapped for lookups; a candidate found there leads to its lemma, filtered by part of speech as in Yomitan, and the form's tags show as its rule chain.
5. **Render.** The overlay sends the results as JSON to the lookup page in a pre-warmed WebView. The page builds the cards; glossaries go through `YomitanRender` (structured content, images served from the engine, each dictionary's `styles.css` scoped to its own entries). `overlay/fonts` supplies the page's `lang`, the phone's font for the language declared by its local name and limited to the script, downloaded or added fonts (limited to the script unless chosen for all text), and the user's CSS, applied last with the page's font list appended to each `font-family`. The page's content security policy lets only stylesheets and fonts come from the internet; scripts, images, media and requests stay on the page's own host.
6. **Highlight and placement.** The matched length of the first result decides how many characters are highlighted. `PopupPlacement` puts the popup above the word, else below the bubble, in landscape beside them on the side with more space (shrinking a little); when that does not fit, the popup keeps its size at the screen's edge on the roomier side and covers part of the word or the bubble rather than getting low or narrow.

Aiming again only repeats steps 3–6; the screen is not scanned again until the bubble goes back to the dock or is tapped.

## Anki export

The page builds the dictionary markers of an entry (glossary HTML with scoped CSS, furigana, pitch, frequencies) because it already has the renderer. Glossary HTML comes from the renderer's tag allow-list with escaped text; each dictionary's scoped CSS goes into a `<style>` element with any `</style` written as `<\/style`, so a dictionary cannot end the element and add markup to the card. `PopupNotes` adds the sentence and cloze markers from the OCR paragraph, the audio clip and, on a long press, the cropped screenshot. The sentence and the crop frame come from the view shown when ➕ is pressed (`NoteSource`); until the scan's final result ➕ is grey and only explains itself (`noteWaitsForText`, the page state's `noteWait`), except for a word from the app's own text; a new scan closes the previous popup; a note that finishes after its scan closed stays out of the next scan (`ScanNotes`); `AnkiNotes` renders the field templates, handles duplicates and talks to AnkiDroid through its content provider. A newly chosen note type gets its templates from `FieldTemplate.guess`: a `NoteTypePresets` entry when the note type's name and fields match a well-known mining note type (its authors' templates, with this app's nearest marker where they use their own), otherwise Yomitan's rule of whole field names with aliases. Media files go to AnkiDroid through a FileProvider.

## Sentence translation

`core:translate` talks to three keyless services: Bing (a key read from the translator's web page, kept for its lifetime and fetched again when the service refuses it), Google's `gtx` endpoint and the translator built into Edge (Microsoft's language codes, no key). Each `Translator` knows its language codes and longest text. `SentenceTranslator` runs the services in the user's order and moves to the next one when a service fails or gives no answer within 3 s; it reports either the text with its service or every service's `TranslationError` (a kind; for HTTP errors the status; for the logs a detail without text, such as an unexpected answer's shape). A certificate that is not valid at the device's date has its own kind, so the user is asked to check the clock. A request runs in the translator's own scope: callers asking for the same text share it, and a success is kept for 10 minutes (16 entries), so a note gets the translation the popup shows. The target is the chosen language or the interface language (`TranslationLanguages.defaultFor`, English when it is the source language).

In the overlay, `SentenceTranslation` connects it to the page and to notes. 文A on the page calls `onTranslate` with a request number; the controller translates the first view's sentence (the same one a note would take) and answers with `showTranslation` (the text, its service and the sentence for the copy button), which the page ignores when it no longer shows that request. The page state carries the view's sentence: a new scan result shown while the popup stays open (`render` with `continued`) keeps the translation when the word and the sentence are the same, and anything else drops it. `PopupNotes` asks `SentenceTranslation.forNote` when ➕ is tapped, so the request runs while a crop editor is open, and fills `{sentence-translation}` once the note is ready, waiting up to 5 s more and leaving the field empty otherwise. The settings page's test calls each service separately with a 15 s limit and keeps nothing.

## Dictionaries

`DictionaryRepository` is the only writer of the registry. Imports (bundled archives, files, downloads, Yomitan collection exports) run one at a time as a foreground WorkManager job: the archive is converted into a staging directory, moved into `files/dictionaries/<uuid>/`, registered, and the engine is reloaded. A dictionary with the same title, or the one an update was started for, is replaced in place. A failed import is reported on its task and does not stop the imports queued after it. Before the engine imports an archive, its title is checked: the engine writes into a directory named after it. An import the process died in is run again by WorkManager, from the start, once: a job whose `runAttemptCount` shows two earlier runs ends with an "interrupted" result instead, so an archive that kills the process cannot loop. As every app start queues the bundled install again, an interrupted bundled install also pauses it until the app's install time changes (an update); the task's "Try again" and a dictionary reset end the pause. "Cancel" on one task stores its id in the preferences (the process may die before the job ends) and cancels the job's body, which runs inside `CancellableRuns`, without cancelling the WorkManager job: a cancelled job ends successfully, so the jobs queued after it still run (cancelling it in WorkManager would cancel them too). Downloads and collection conversions check for the cancel between reads; the engine's import of an archive runs to its end, and the repository checks again before it registers the result. A cancelled or given-up job deletes the copy of the picked file it was to read and gives back the kept access to it. Each job is tagged with the name of the archive it reads, and the first import job of a process removes what earlier processes left: directories of no registered dictionary, staging directories, and downloaded or copied archives that no unfinished job reads (when an unfinished job from an older version has no such tag, only archives older than six hours). Orphaned directories are listed under the registry lock, so the list never holds a dictionary between its move and its registration, and deleted after it, so lookups do not wait for large deletions.

A Yomitan collection export is one JSON file with the rows of all dictionaries, table by table. `YomitanBackup` reads it twice as UTF-8 bytes without decoding row values: first to measure the chosen dictionaries (`measure`), then to copy their rows into one Yomitan archive per dictionary (`convert`). `CollectionSpace` turns the measurement into the peak storage of the import (all archives exist before the first one is imported, each is deleted after its dictionary is installed) and decides whether the archives are stored uncompressed (fastest), deflated (when only that fits), or not written at all (the task fails with the needed and free space).

`DictionaryReset` returns the dictionaries to a fresh install: it cancels the import jobs by tag and waits until no worker is inside its body (`DictionaryImports.cancelAll` counts them), forgets the bundled installs, deletes every dictionary through `DictionaryRepository.deleteAll`, and queues the bundled archives again. Before it deletes anything it stores the number of the run in the preferences and removes it once the bundled archives are queued; `resumeInterrupted`, called at app start, runs the reset once more after a first run the process died in, and after a second one gives up and stores a flag. The start screen shows that flag once in a dialog, and the Dictionaries screen as a card until it is closed or a reset succeeds. The queued install continues as any import does. A reset that fails with an exception is reported on the Dictionaries screen and not run again by itself. `phase` (deleting, then installing until that import job finishes) drives the spinner that replaces the screen's reset icon.

## Settings reset

All settings live in one preferences DataStore. Its provider keeps the settings as last read (`SnapshotDataStore`), and every repository offers a `cached` value from it, so a screen's first frame shows the user's values rather than defaults that change a moment later; reads and writes still go through the DataStore. Data from outside the settings is kept the same way while the app runs: AnkiDroid's last answer (the Anki screen shows it dimmed and without taps until AnkiDroid answers again, `Modifier.pending`), the Dictionaries screen's last state, the dictionary list, the launcher apps and the popup's typefaces. `SettingsReset` removes stored keys rather than writing defaults; `SettingsKeys` maps key names to the settings page that resets them (the global reset also clears update announcements and one-time hints). Dictionary bookkeeping, migrations and the interface language (kept by Android) are never touched. Leaving e-ink mode goes through `EInkSizes.restore`, and the Background page's reset also stops the keep-alive service. The popup CSS editor saves after a pause, so its reset first replaces the pending text with the default; text fields that keep their own copy (the Anki tags) take the new value once they lose focus, and confirming a reset clears focus.

## Backup and restore

`app/backup` writes one zip: a manifest (format version, app version, sections) first, then the preferences as typed JSON grouped by section (`BackupPreferences`: key prefixes decide the section; internal state such as one-time hints is left out), the dictionary list (registry entries without ids, matched by title on restore), the popup fonts, and optionally each dictionary's converted directory. Restoring reads the zip as a stream: checked preference sections are replaced in one DataStore edit, fonts and dictionaries are staged and handed to `PopupFonts.restore` and `DictionaryRepository.restore` (a dictionary with the same title is replaced in place and keeps its id, switch and priority), and the dictionary list is applied last to whatever is installed. `BackupManager` is a singleton with its own scope, so the work goes on when the screen is left.

## Updates and releases

`update/AppUpdates` reads the latest stable GitHub release, picks the APK for the device's ABI, checks that it is a newer Screenlate signed with the same certificates and installs it through `PackageInstaller` (`UpdateReceiver` gets the session status). The version comes from git tags: `vX.Y.Z` gives the name X.Y.Z and the code X·10000 + Y·100 + Z (`build-logic`'s `ScreenlateVersion`). CI (`.github/workflows`) builds and tests every push, and a tag builds per-ABI and universal APKs, a source archive with submodules and a changelog for the GitHub Release.

## Languages

Language is a parameter of OCR, lookup and rendering (`core.common.Language`). Whatever differs between languages lives behind `LanguageSupport`; Japanese and English are implemented so far.

`LanguageProfiles` (`core:common`) keeps the turned-on languages and the active one in the preferences. Settings kept per language use their old key for Japanese and the key with `_<code>` for other languages. The application settles the first run before anything writes preferences: any stored preference or installed dictionary means an upgrade, which keeps Japanese on; a fresh install opens `FirstRunScreen` first. `LanguageSwitch` (`app`) turns a language on, queueing the downloads chosen on `LanguageSetupScreen` as ordinary imports, and off, optionally deleting its dictionaries and models and cancelling their unfinished downloads. The bundled dictionaries are Japanese, so the import worker installs them only while Japanese is on. A dictionary belongs to its source language, which an import takes from the matching catalog entry first, then from index.json (where Wiktionary's `all` names no language), then from the replaced dictionary, then from the archive's content. The start screen reports, per turned-on language, the mandatory catalog categories that no enabled dictionary covers, with the progress of the queued imports.

On-device recognition: ML Kit's Japanese, Chinese and Korean models are bundled (the Japanese one reads Latin too); each script gets its own recognizer. A script without an ML Kit model needs a `ModelOcrEngine`, whose code is in the APK and whose models are catalog entries of the category `OCR_MODEL`: the import worker downloads them like dictionaries and hands them to `OcrModelStore`, which installs a file only when its SHA-256 matches the pinned one, unpacks zip archives, keeps a version per model and replaces an older one. Several languages may share a model (a text detector); turning a language off deletes only the models no other turned-on language uses. `DeviceOcr` asks ML Kit first, then the engines whose installed models read the language; a language the device cannot read goes to the cloud alone, and a device-only scan of it fails with a message. Lines carry their direction: a horizontal line whose first strong character is right-to-left is split into characters from its right edge.

The interface language is separate: string resources in 14 locales, chosen in Appearance or in the system's app language settings (Android 13 and newer). The system applies a per-app language to activities only, so the application object and the accessibility service return resources in that language themselves (`AppLanguageResources`); the bubble, popup, crop editor and notifications follow it.

## Privacy

Imports, deletions, resets, update checks and the bundled install log each step with ids, sizes, timings and dictionary titles, so a shared log shows where one went wrong. Logs never contain recognized text, looked-up words, note contents or URLs with terms: exceptions are logged through `redacted()`, which keeps the type and stack but drops messages, and URLs through `redactUrl()`. The app logs only to logcat, the system's fixed-size ring buffer, so nothing piles up on the device; files are written only when the user shares or saves the log. A scan logs its stages with timings (capture, app text, cloud request, on-device bands, draft and final), and events such as docking, note results and audio lookups are logged as outcomes and counts, never per aim movement. Translations log the service, the time and the error kind, never the sentence or its translation; the sentence itself goes only to the translation services, and only when 文A is tapped or a note's template has `{sentence-translation}`.

## Tests

- JVM unit tests next to each module: OCR protocol and layout, `CompositeOcr` with fake engines, sorting, spelling variants and romaji, sentence ends, the OCR model store and the choice of on-device recognizer, collection conversion, notes with a fake `AnkiBackend`, audio sources against MockWebServer, fonts and the CSS checker, the backup format and archive, popup placement.
- Page scripts: `scripts/page-tests` runs `note.js`, `anki.js`, `definition.js` (with the Japanese rules in `definition-ja.js`) and `popup.js` in jsdom under `node:test`.
- Instrumented tests: the engine with small dictionaries (also an English one looked up through Yomitan's language code, with a form-of entry) and the whole lookup pipeline, the dictionary registry, the lookup page in a WebView, the text selection menu entry (`ProcessTextTest`), and an AnkiDroid round trip that skips itself without AnkiDroid.

## Threading

- The overlay runs on the main thread of the accessibility service; OCR, lookups and file work suspend on IO or Default dispatchers.
- The hoshidicts session is used from one coroutine at a time (a mutex in `HoshidictsEngine`); imports do not touch the session and run in parallel with lookups.
- `DictionaryRepository.withLookup(language)` holds the registry mutex from loading a language's dictionaries through its queries, including glossary image reads, so another language's lookup, CSS read or registry change cannot replace them mid-query. A note keeps the language captured when adding it, including its sentence parsing and glossary images.
- The lookup page talks to Kotlin through `@JavascriptInterface` methods, which post to the main thread.
- The popup's WebView renderer runs at a priority the system may lower while the popup is hidden (`setRendererPriorityPolicy(…, waivedWhenNotVisible = true)`); if the renderer is reclaimed, the page is recreated at the next scan. The search screen's embedded page keeps the default priority.
- A cancelled ML Kit task cannot be stopped, so the on-device pass works on its own copy of the screenshot and frees it when the task ends.
- Recognition is collected on the main thread, so the engines move their heavy work off it: screenshot copies and crops, ML Kit's line building and the cloud engine's image encoding on Default, the cloud request and its response on IO. Screenshot callbacks copy the image on a background executor.
- The scan's screenshot is shared by the scan, its recognition, its small-text bands and a note being added, whose crop editor draws it (`SharedScreenshot`): each user retains it and releases it when done, and the last one frees it. A note releases it as soon as the editor returns its crop. Closing the scan (docking, rotation, hiding the bubble) closes an open crop editor as cancelled; a note already being added goes on, but a picture is no longer taken for it.
- Values derived from the installed dictionaries (styles, tag descriptions, frequency modes) are kept until the registry changes (`DictionaryRepository.generation`).
